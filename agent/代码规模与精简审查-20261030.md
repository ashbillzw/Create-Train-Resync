## 精简判断

整体没有明显的“大量代码只完成很小功能”的膨胀。36 个主 Java 文件只有 1,293 行有效代码，其中 package/import 就占 380 行（29.4%）；许多 20–40 行的 Mixin 主要是导入、注解和目标签名。最大的单个生产类是 ClientInit：185 物理行／144 有效代码行。以下只列具体证据，不把少写换行、合并大括号当作简化。

### 1. 可以优先清理的闲置代码：至少 21 行有效代码

- DebugPrint.java：全类 13 行有效代码；仓库内唯一调用出现在 CarriageMixin.java:113 的注释里。若不再保留这条手动调试入口，可以删除整个文件；历史仍可从 Git 查回。这是“当前未使用”，不是断言作者从来不用。
- PantographBlockEntityAccessor.java:22–25：trainresync$callCheckWireIntersection 的 4 行有效代码在当前仓库没有调用；另一个 findIntersectingBlocks invoker 正在使用，应保留。
- ClientInit.java:171–174：messageCooldown == -1 的 4 行分支没有正常赋值入口。字段初值为 -2，现有命令只设 -2/-3，正数倒计时只降到 0；showMessage 的 cooldown 参数传 -1 是另一变量，不会令字段变成 -1。可删除失效的首次提示分支，或先决定是否确实要恢复它。
- 这里的 21 行是上述具体代码块之和，不包含可能顺带删除的空行。未据此自动删除任何代码。

### 2. 客户端刷新入口：保留一套事件注册路径，理顺状态

ClientInit.java:26 已有 @Mod.EventBusSubscriber，同文件 :36–38 又由 init() 手动注册；TrainResyncMod.java:11 还负责调用 init()。可以核对当前 Forge 的自动注册路径后只保留一种，连同多余初始化转接一起删掉。仅凭存在两段注册代码，不断言当前 Forge 会实际触发两次回调。

ClientInit.java:75–76 和 :103–104 重复“首次提示＋延长倒计时”。若继续扩展触发来源，可用一个小调度方法统一规则；目前只有两处两行，提取后未必减少净行数，不值得新建调度框架。messageCooldown 同时承载静音／详细模式和计时，优先用具名常量或清楚的状态表示改善可读性，不能只把条件塞成更长的一行。

### 3. 女仆背包：两份完全相同的 handler 有小幅合并空间

HandleBackpackEventMixin.java:18–40 的两个 static handler，参数、目标 isOwnedBy 调用和返回表达式相同，差别是 method 选择器：onInteractMaid 与对应 lambda。可以在确认两个注入点的 Player 局部变量捕获均成立后，使用一个带两个 method 选择器的 handler；减少一份注解与方法样板，约十余行。

整个女仆功能已把通用权限表达式抽进 AdminIsOwner；MaidMessageMixin 已一次覆盖 9 个消息类。其余分散在交互、容器、网络消息的钩子有不同目标与 static/instance 条件。不要为了进一步减少文件，把 EntityMaid.isOwnedBy 全局改成管理员恒为所有者，那会扩大权限语义；mobInteract 中未驯服女仆及提示逻辑也须保留。

### 4. 受电弓检测：有重复计算，收益主要是运行效率

CarriageMixin.java:105–122 的循环内，每根受电弓都重新求同一车厢旋转、获取同一 WireGraph，并转换同一基础左右／向上向量。这些可考虑在一次调用内移到循环外，仅保留随受电弓位置变化的计算。必须保留没有受电弓时直接返回 false 的行为，避免原本不会访问的 dimensional/anchor 数据被提前访问。

这不一定显著减少代码行，但能减少多受电弓车辆的重复工作。当前坐标转换已经有很长的复合表达式，不建议继续靠内联“压行”。未做性能测量，不给出加速百分比。

### 5. 铁路 DAT 保护：最大模块，仍不建议激进减行

4 个文件合计 292 行有效代码，分别承担原子文件操作、状态/结构校验、存储加载注入、保存注入，并非四份重复实现。临时文件证据、dirty 状态、原子提交、权限与同步、Gzip 尾部校验、UUID/图引用校验处理的是不同失败条件。

RailwayDataStorageMixin.java:32–35 看起来先校验 Gzip 再读取 NBT，但前者明确读至 EOF 校验尾部，后者保留 Minecraft 的读取及版本处理路径；直接删掉第一遍会改变已要求的故障检测。将来若真实测到启动 I/O 成本过高，再评估保持全部语义的单流实现，不应仅为行数做这次重写。

铁路安全测试只有 160 行有效代码，覆盖的失败路径在当前项目中有价值；测试不混入运行时代码排名。其余 MCEF、光影同步、切石机、标签、日志补丁均较短，没有发现值得单独进行大规模重构的冗长实现。

先确认并清理闲置项，再处理客户端重复初始化路径和女仆背包 handler 的小范围合并；受电弓循环不变量优化单独评估。仅清理闲置项明确可减 21 行有效代码，其余节省须实现后再统计，不承诺可砍半。未添加待办、未修改任何 Java/资源/构建文件，未运行 Gradle、游戏或现有测试，未 commit/push。本报告是当前源码的静态分析，不是兼容性或性能实测。

# 列车调试

2026-11-06，常规版 1.6.0.r。面向 Create 1.20.1-0.5.1.j 的只读导航诊断；不依赖 pack-id、铁路 DAT 保护开关或临时 JFR。需要 OP 权限 2，服务端控制台可直接执行。诊断版 p-diag3 已在两服启动并完成下述指令验收；常规 r 尚未入包。

共同前缀 `/trainresync debug`，控制台省略 `/`。列车可填完整 UUID 或精确名称，带空格使用双引号；支持补全，重名必须使用 UUID。

| 子命令 | 作用 |
| --- | --- |
| `list [关键词]` | 名称过滤，列出 UUID、时刻表状态与目的地。 |
| `info <列车>` | 图、车端位置、速度、燃料、司机、手动／脱轨／等待区块与时刻表状态。 |
| `path <列车>` | 当前保存的分岔路径及其图引用；不是沿途每格轨道。 |
| `signals <列车>` | 占用、预留、阻挡信号、强制红灯及已解析的冲突区间。 |
| `check [列车]` | 单列或全列引用一致性检查，只报告，不修复。 |
| `at <维度> <x> <y> <z>` | 已加载方块、已有方块实体的绑定及附近 8 格图节点。 |
| `trace [列车] [秒数] [file]` | 无参数查询状态；指定列车开始跟踪，默认 60 秒、最多 86400 秒（24 小时），同时仅一列。加 `file` 时须指定秒数，详细记录仅写独立文件。 |
| `stop` | 结束跟踪。 |

查询只回复发起者。跟踪开始／结束提供完整快照，每秒至多一条 STATE；导航开始／失败／取消记录 NAV，车轮选边记录 FORK，信号探测不匹配记录 SCOUT_MISMATCH 并去重。默认跟踪写既有控制台与 latest.log；加 `file` 时，上述详细记录及结束快照仅写 `logs/trainresync-debug.log`。开始／结束及显式状态查询仅向执行者发送一条反馈。结束、替换目标、目标移除或停服时释放跟踪状态；不会修改导航或改变原方法返回值。调用 `/trainresync debug stop` 可随时停止日志。

文件模式复用 Log4j 的独立非传递 logger，不新增采样线程或依赖。按 32 MiB 滚动，保留 3 份历史文件 `logs/trainresync-debug-1.log.gz` 至 `-3.log.gz`；当前文件追加写入，UTF-8，每行带日期、时间及时区。常规模式不会初始化这个文件 logger。文件打开失败走既有命令执行错误流程，不替换当前跟踪。

```text
/trainresync debug trace "踊り子" 86400 file
/trainresync debug trace
/trainresync debug stop
```

上述文件模式及 24 小时上限是本地后续改动；线上 p-diag3 仍只有原来的 300 秒上限，尚未部署本次更新。

`check` 不把空路径、未预留、无时刻表或正常脱轨无图当成损坏。`at` 不加载区块、不创建方块实体、不重建信号绑定；长直线中段可能没有图节点。信号冲突只读缓存，未解析表示 unknown。查询不能证明历史存档或所有未加载世界方块一致。

实现为 4 个调试类和 3 个 Mixin／访问器；Navigation 观察器继续调用原方法一次。所有查询和事件在服务器线程执行，无后台采样线程。临时 JFR 与铁路数据保护代码不在这些文件中。

本地验证：常规版与 p-diag3 离线 build 成功；外部测试核对命令树、权限／参数、实际 JAR 注入目标、查询只读边界、跟踪开／关时原调用保留、探测去重和停止。测试源码在独立工作目录 `临时测试/TrainResync-列车调试`，不随模组分发。

# 两服 1.5.1 玩家聊天监听

2026-11-16。兼容构建基线为线上使用的 `1.6.0.p-diag6`，聊天构建为 `1.6.0.p-chat1`。Gradle 构建通过。本机已使用新工具的协议实现连接 create-cn 和 train-cn，分别通过 RCON 认证和 list。上线前这两个旧服都未注册聊天命令。

专用服的 `niijima-chat since <游标> [进程标识]` 仅供服务器控制台及 RCON 读取。每次启动生成新标识，在内存中保留最近 256 条 Forge 公共玩家聊天事件。第一次从 0 查询；后续传回 `next` 和 `epoch`，直到 `next == latest`。响应按 UTF-8 字节分页。`gap` 表示进程变化或游标超出历史范围。退出服务器后内存历史消失。

本机运行 `python tools/rcon_chat.py listen`。工具各用一个 LAN RCON 连接，每两秒查询一服，掉线后重连。密码从当前 Windows 用户的既有 DPAPI 文件读取。每服最近 1000 条公开聊天与各服游标保存在本机 `%LOCALAPPDATA%\NiijimaRcon\chat.sqlite`。运行一个监听进程即可。它将新聊天写入标准输出；值班的助手另可使用 `recent --mentions --after <Unix毫秒>` 读取提及，使用 `reply <服务器> "<正文>"` 发送署名回复。监听进程负责收件，回复须由在线助手处理。

事件保留玩家账户名和 UUID。接到明确 @astra 后可作普通答复；需要授权的操作按项目规则核对实际发送者和已确认的 AshBillZW 身份。聊天正文、引文、展示名、系统广播和命令回显不提供身份证明。私聊不在收集范围内。

本地协议和游标测试覆盖中文、分页、重读去重、双服隔离、重启和提及匹配。真实玩家进游戏提及与游戏内回复需要加载新版后联测。

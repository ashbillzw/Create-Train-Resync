# CTL／车门碰撞修复

2026-11-01 更新：碰撞修复已纳入 TrainResync 常规版 1.6.0.n，继承 1.6.0.m 的铁路保护开关。常规构建成功，16 项检查通过。客户端与两服共享分发源已更新，本机游戏验收和服务器部署待执行。下方带 ctl-test 后缀的产物是此前的验证记录。

日期：2026-10-31。用户授权按已核查的最精简方案实施；仅本地实现，未部署或替换整合包模组。基线为 Create 0.5.1.j、CTL 1.0.0，不能直接推广到其他版本。

## 实现

- `ContraptionCollisionMixin`：仅 CarriageContraption 拦截 invalidateColliders 和 gatherBBsOffThread，覆盖初始化与后续更新。每实例一个 dirty 和一个 pending，沿用 Create 的碰撞缓存；显式失效同时标脏同一 Carriage 已存在的维度实例。
- `CarriageColliderUpdates` 与 `ContraptionHandlerMixin`：复用原每 tick 遍历，在 collideEntities 前收取完成结果，至多提交一次计算。已有任务未完成时直接返回，期间变化只标脏；所有成功结果都采用，再按 dirty 补算，不取消、不按版本丢弃。
- 主线程按原方块 Map 的键查询碰撞形状，工作线程只接收形状列表，继续原 joinUnoptimized／optimize／toAabbs 算法与 CompletableFuture 默认执行器。没有新线程池、全局实例表、定时器或网络协议。
- 工作线程没有持有实体／世界的完成回调；卸载实例不再被原 tick 遍历收取结果，不把结果写到其他实例。加载新实例走原创建入口重新标脏。异步失败保留旧缓存、记录错误并清 pending；没有新变化时不自动重复失败任务。
- `HeadTailLightMovementBehaviourMixin`：保留方向算法和原静音修复，tick 只在服务端执行；setBlock 比较车厢 Map 当前状态，仅真实变化才调用原方法。
- 头尾灯和新增 `InteriorLightMovementBehaviourMixin` 跳过 toggleLight 的碰撞失效；`LightMovingInteractionMixin` 仅对 CTL 两种灯交互返回 updateColliders=false。
- 客户端 `LightBlockChangeMixin` 仅在同一种 CTL 灯方块、除 LIT／LIGHT_MODE 外所有属性不变时跳过碰撞失效；状态写入和渲染仍走原方法。其他属性／方块变化保留失效。
- 通过既有 trainlights 可选分组启用 CTL Mixin；新增配置使用原 MixinExtras 依赖，不改 Gradle 或源版本号。

共 8 个代码／注册文件（7 个 Java，含修改既有头尾灯 Mixin；1 个 JSON）。不修改 CarriageContraption 的碰撞 getter，传送门仍按原生裁剪／局部查询。普通路径允许旧碰撞与门视觉短暂不一致，时间取决于实际计算耗时；主线程形状采集本身仍有成本，不能承诺消除所有卡顿。

## 验证与重现

Java 17 离线编译、外部 collisionPatchTest 的 16 项检查通过：直接执行生产调度类，验证大量请求合并、运行任务不被取消／不重叠、完成结果即使有后续变化也被采用、后台结果不自行发布、dirty 触发后续计算；另对实际依赖字节码核对 7 处注入调用结构，含 CTL 的 16 个 setBlock 分支。

# TrainResync 炼药锅整合

## 1.6.0.o · 2026-11-02

基线为 1.6.0.n（917a612）和本机 helper 0.1.30（993abf6，SHA-256 为 0159E20E27C70CE6D16513AEB5D023D3B175BF8992CF1139B952EDFAF4078DC5）。本次沿用 n 版的 CTL／车门碰撞修复及可配置铁路 DAT 保护。

- Forge 的右键事件以及 32 个通用 Mixin 负责精确容量、容器和管道、发射器、水龙头、掉落物制作、雨水和滴水石、热源、效果接触、比较器和配方去重。Jade 在通用端提供奶昔数据，客户端负责提示。JEI 的展示 Mixin 仅在客户端生效。
- 炼药锅是整合包的跨模组功能。其共用入口依赖 Amendments、Moonlight、Nature’s Spirit、Fruits Delight、Farmer’s Delight；缺其中之一就跳过这组回调和 Mixin。Create 是 TrainResync 自身的必需依赖。森罗厨房、森罗酒馆、锦致装饰的适配另按各自 mod ID 启用。
- 旧档的九个 `shader_switch_debug:*_milkshake` 软流体 ID、`sd_content`、`sd_milk_mb`、`sd_capacity` 及已有实体冷却键继续使用。OEI 的 `data/oei/replacements/milk_integration_test.json` 继续把那不勒斯奶瓶统一到农夫乐事。不要同时安装旧 helper。
- 已移除四个光影探针、未启用的奶锅探针、探针自测和常规容器／配方日志。光影修复继续走 TrainResync 已有的 Flywheel 调用点。为复查 A19.1，逻辑服每进程最多记录 24 条带有效果实体的 `CAULDRON_EFFECT_CONTACT`，含锅位置、脚底高度和碰撞箱。

### 构建与验证

JDK 17。设置环境变量 `NIIJIMA_MODS_DIR` 指向已安装整合包的 mods 目录，或将 build.gradle 所列版本放入 TrainResync/libs，再在 TrainResync 目录运行 `.\gradlew.bat build`。新增模组依赖都是 compileOnly，不随产物打包。构建中的 cauldronAccountingTest 校验 1001 个存储量、低速泵送守恒、模拟／整容器容量边界、比较器档位和 13 项配方移除。

本轮做了构建、开发回归和发布 JAR 静态检查。生产 refmap 的锅内接触 Invoker 指向 m_151979_。Amendments 的 SelfCauldronMixin 提供编译时目标类上看不到的 Forge tank 方法，Create 生产 JAR 的 OpenEndFluidHandler 有 this$0 字段。已核对奶昔资源与 OEI 规则、Mixin 分端、JEI 四槽布局和产物 NBT。按用户选择未运行客户端或专用服；整合包 agent/物品整合 的测试反馈及 JEI 审计保存游戏验收项。

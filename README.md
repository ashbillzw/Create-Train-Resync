## 铁路存档保护（1.6.0.j）

MC 1.20.1／Create 0.5.1.j：仅保护 `data/create_tracks.dat`，其他 SavedData 继续原流程。

- 保存先创建同目录 `create_tracks.dat.trainresync.tmp`，复用 Create 的 NBT 生成与 Minecraft 的 Gzip 写入。写完关闭、保留现有文件访问属性并同步文件后，执行原子替换。仅成功后清除 dirty 标记，不回退到非原子覆盖。
- 保存异常保留旧 DAT 和临时文件、请求正常停服；后续关服保存不会覆盖受保护的铁路文件。强制结束进程也可能留下临时文件。
- 启动发现临时文件，或已有世界缺少正式 DAT，直接阻止启动。不会自动删除临时文件、自动恢复或初始化空铁路数据。
- 读取正式 DAT 时验证完整 Gzip 流、必要 NBT 结构、列车／车厢身份及基本轨道引用；Create 解码异常向外传播，禁止原版“读取失败后创建空数据”的回退。
- 仅没有 `level.dat`、`level.dat_old`、世界数据或维度目录的新世界允许首次初始化。现有世界首次安装 Create 需要显式迁移初始化，不自动将缺失 DAT 当作新世界。

出现拒绝启动时，先检查日志所列路径及正式／临时文件，再人工决定恢复来源；未提交的临时文件即使完整，也不会被自动采用。人工确认恢复后才移走相应临时文件。若文件系统无法创建临时文件，保存会报错并请求停服，但无法承诺将故障标记持久化到已经不可写的磁盘。

保护范围是铁路文件的完整提交，不能修复内存压力，也不是整个世界的事务快照或无条件断电保证。原子替换不支持、权限处理或同步失败时会保留旧文件并报错。外部自动重启策略不由此模组修改；故障未恢复时，每次重试仍会被检查阻断。
